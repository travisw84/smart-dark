# Review of the Smart Dark build, 23 October 2026

Reviewer: claude-sonnet-5-5, read-only. I read the full source and ran the tests myself. I then probed the built extension in a disposable Chromium profile with synthetic pages. Nothing in the repo was changed except these files. They are uncommitted.

## Verdict

The security and privacy design is sound, and the 42 checks pass (19 unit, 23 browser). The theming engine is not ready for real browsing. The test pages have fewer than ten elements, so they hide four problems that appear on ordinary pages. The earlier claim that this is quick enough for realtime browsing is not supported for pages with more than about a thousand elements.

## Findings, most serious first

1. **Theming stalls on larger pages.** `process()` in `src/renderer.js` disables the extension stylesheet before reading original colours. The first `getComputedStyle` call then forces a full style recalculation. On a big page that recalculation costs more than the 5 ms budget, so the loop stops after one element per animation frame. Measured on synthetic pages of plain spans:

   | Elements | Themed at 0.5 s | Themed at 6 s  |
   | -------- | --------------- | -------------- |
   | 300      | 304 (all)       | 304 (all)      |
   | 1,000    | 638             | 875            |
   | 3,000    | 411             | 716            |
   | 8,000    | not measured    | 883 after 30 s |

   The 8,000 element page also logged about 100 long tasks of 50 to 200 ms. Fix: start the time budget after the first read, batch hundreds of elements per recalculation, and stop toggling the sheet every frame.

2. **Hover, focus and active styles freeze.** Each element gets a static `!important` colour taken from its resting state. On a button with `a.b:hover{background:#0a7}`, the original page turns green on hover. With the extension it stayed `rgb(20, 22, 28)`. Sites lose their interactive feedback. Handling this properly means rewriting colours inside the site's own stylesheet rules, which is how Dark Reader keeps hover states. That is a larger change than a patch.

3. **Modern colour syntaxes are skipped.** `parseColor` in `src/core.js` understands hex, `rgb()` and `color(srgb)`. Chrome returns `oklch()`, `lab()`, `color-mix()` and display-p3 values unchanged from `getComputedStyle`. On a page using `oklch()` backgrounds (Tailwind v4 does), nothing changed: body and card stayed `oklch(...)`, detection reported 0 samples and `unknown`, and the renderer reported itself active. Fix: convert any CSS colour to sRGB through a cached 1x1 canvas readback.

4. **Jev decisions do not persist, and often cannot land.**
   - Any DOM mutation, scroll, input or change event sets `decision = null` in `src/content.js`. After a `use_original` decision restored the light page, one `scrollBy` turned it dark again, and one appended text node did the same. In normal use the restore-original result lasts until the next scroll.
   - In-flight results are discarded when the document revision changes. On a page that updates every 500 ms, two of three manual checks succeeded and the third was discarded. My mock answered instantly, so real provider latency of seconds will discard far more. Automatic mode made one capture in 14 s on that page and never reached the provider.

   The race protection is correct. Using one revision counter for every change is too blunt. Track visual change in the captured viewport, and keep an applied decision per page.

5. **The measurements in the docs describe the fixtures.** The ~100 ms figures come from pages with a handful of elements. The popup line "Detection: N ms" times only the sampling step, not the theming that finishes seconds later. `docs/verification.md` says the numbers are fixture-only, but the README and popup read as a general claim.

## Minor

- `FETCH_CSS` in the worker fetches any http(s) URL a content script sends, with credentials omitted and only `text/css` bodies returned. That is still a way to read local and intranet CSS. Restrict it to the sender's own stylesheet URLs. It runs only in Dark Reader mode.
- The vision cache key includes a digest of the JPEG, which changes between captures, so the cache will almost never hit. It does no harm, but the README implies it saves requests.
- Native activation only covers sites with a class or data-attribute toggle. Sites that rely only on `prefers-color-scheme` get the custom renderer. How many real sites this affects is unmeasured.

## What holds up

- Key storage, the trusted-sender check for settings, no key in content scripts, `redirect: "error"`, `credentials: "omit"`, a response size cap and a bounded model vocabulary all read correctly.
- The embedded-frame check before upload, the session-only digest cache and the serialized settings writes address real review findings and have regression tests.
- The docs are honest that live Jev accuracy is unverified and that the Opus review did not run.

## Not verified

No real website was loaded. No live Jev call was made. Opus did not review this. The probes use synthetic pages and a mocked provider, so the numbers above are indicative. The hover and `oklch()` results are the most certain.

Probes: `docs/review-probes/behaviour-probe.mjs` and `docs/review-probes/scaling-probe.mjs`. Run with `node` after `npm run build`.

## Status after fixes, 23 October 2026

1. Theming stall: fixed. The renderer mirrors stylesheet rules and no longer reads styles per element. A 6,000 element page is dark in 142 ms.
2. Frozen hover and focus styles: fixed for everything the site's stylesheets define. Elements tagged by the second pass (inline styles and leftovers) still keep a snapshot colour on hover.
3. Colour syntaxes: fixed. oklch, oklab, hsl, hwb, color(srgb) and hex with alpha are parsed directly. Named colours, lab, lch, color-mix and wide gamut colours go through a canvas readback.
4. Jev decisions: fixed. A decision stays with the page until you navigate, change settings, or its overall colours change. An automatic check lands on a page that keeps updating, even with a slow provider.
5. Documentation: README and popup copy updated. The popup no longer shows a detection time as if it were render time.

Minor items: the stylesheet fetcher now refuses private-network addresses on another origin. The vision cache key uses the page URL and the coarse look of the page, so it can hit. Native activation coverage is unchanged.

Found later with real websites and fixed: sites that reset the theme attribute (MDN), sites that remove style tags from the head, shorthand colours hidden behind variables (Wikipedia), and dark transparent logos that disappeared on dark pages.
